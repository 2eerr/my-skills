# TRACKER.md — Content Inventory Tracker

The exact file format and generator-script contract for `TRACKER.md` — the single
source of truth for page-creation progress on a local-SEO site. The file is
**generated**, never hand-edited. Read the project's config for region/location
naming — never hardcode.

## When to use it

- Setting up a new project's tracker for the first time.
- Writing or debugging the generator script that produces `TRACKER.md`.
- Verifying the tracker matches the content folder after a batch.
- **Not for:** writing page content (see `seo-content-writing`), the autopilot loop
  (see `seo-autopilot`), or geographic/service data (see `seo-location-model`,
  `seo-service-catalog`).

## File location

`TRACKER.md` at the project root (or wherever the project's docs live). The generator
script typically lives in `source/scripts/gen-pages-tracker.js` (or equivalent).

## Status symbols

| Symbol | Meaning | Generator behavior |
|---|---|---|
| `[x]` | Content exists with `unique: true` in frontmatter | Derived automatically from filesystem |
| `[~]` | In progress — claimed, no unique content yet | Preserved across regenerations (manual claim) |
| `[!]` | Exists but not unique — flagged for rework | Preserved across regenerations (manual flag) |
| `[ ]` | Missing / not started | Derived automatically from filesystem |

**Generator rule:** `[x]` and `[ ]` are derived from content files. `[~]` and `[!]`
are **manual flags** that survive regeneration — the script must never overwrite them
when it re-runs.

## File layout (section by section)

### 1. Header

```markdown
# TRACKER.md — Generated Content Inventory

> Auto-generated by `source/scripts/gen-pages-tracker.js`. Do not hand-edit.
```

Replace the script path with the project's actual generator script path.

### 2. Summary table

A table showing unique vs total pages per category, with a bold total row.

```markdown
## Summary

| Category | Unique Pages | Total Pages |
|---|---|---|
| Core | {N} | {N} |
| Hubs | {N} | {N} |
| {Region type} | {N} | {N} |
| {Location type} | {N} | {N} |
| Money | {N} | {N} |
| **Total** | **{N}** | **{N}** |
```

**Column rules:**
- **Unique Pages** = count of files with `unique: true` in frontmatter for that
  category.
- **Total Pages** = the theoretical maximum for that category (e.g. all qualifying
  locations × all services for Money).
- The **Total** row is the sum of all categories above it.

**Category names** follow the project's own terminology — e.g. `Core`, `Hubs`,
`States`, `Cities`, `Money` or `Regions`, `Locations`, `Hubs`, `Money`.

### 3. Legend

Immediately after the summary, a legend explaining the status symbols:

```markdown
---

Legend:
- `[x]` unique
- `[!]` exists but not unique
- `[~]` in progress (currently being written — claimed per {region}, only while actively worked)
- `[ ]` missing / not started
```

The `{region}` placeholder matches the project's region type (e.g. "state").

### 4. Core Pages section

Lists every core page (homepage, about, contact, FAQ, legal, etc.).

```markdown
## Core Pages ({N}/{N} pages) ✓

- [x] `/` — Homepage
- [x] `/about/` — About
- [x] `/contact/` — Contact
- [x] `/faq/` — FAQ
- [x] `/privacy/` — Privacy Policy
- [x] `/terms/` — Terms of Service
- [x] `/services/` — Services Overview
- [x] `/locations/` — Locations
- [x] `/404/` — 404 Error
```

**Line format:** `- [{status}] `{URL}` — {Page Name}`

**Section header:** `## Core Pages ({unique}/{total} pages) ✓` — the `✓` appears
when all pages in the section are `[x]`.

### 5. Service Hubs section

Lists every service hub page.

```markdown
## Service Hubs ({N}/{N} pages) ✓

- [x] `/services/{service-slug}/` — {Service Name}
- [x] `/services/{service-slug}/` — {Service Name}
```

**Line format:** `- [{status}] `/services/{slug}/` — {Service Name}`

**Section header:** `## Service Hubs ({unique}/{total} pages) ✓`

### 6. Region/State Pages section

Lists every region (state, province, etc.) with its qualifying location count.

```markdown
## {Region type} Pages ({N}/{N} pages) ✓

- [x] `/{region-slug}/` — {Region Name} ({N} {location type}s)
- [x] `/{region-slug}/` — {Region Name} ({N} {location type}s)
```

**Line format:** `- [{status}] `/{region-slug}/` — {Region Name} ({N} {location type}s)`

The location count in parentheses is the number of qualifying locations in that
region.

**Section header:** `## {Region type} Pages ({unique}/{total} pages) ✓`

### 7. Money Pages section (nested by region)

The most complex section — nested under region sub-headings with per-region
summaries and per-location rows.

#### 7a. Section-level legend

```markdown
## Money Pages ({N}/{N} pages) ({N}/{N} {location type}s)

Legend:
- `[x]` — {location type} content exists + all {N} money pages unique
- `[~]` — in progress / claimed
- `[!]` — some money pages exist
- `[ ]` — not started
```

**Section header:** `## Money Pages ({unique money}/{total money} pages) ({complete locations}/{total locations} {location type}s)`

#### 7b. Per-region sub-heading

One sub-heading per region, showing that region's progress:

```markdown
### {Region Name} ({abbrev}) — ({unique}/{total} pages)  ({complete}/{total} {location type}s)

- [x] `/{region}/{location-slug}/` — {Location Name} — {population} — [x] {N}/{N} money pages
- [x] `/{region}/{location-slug}/` — {Location Name} — {population} — [x] {N}/{N} money pages
- [~] `/{region}/{location-slug}/` — {Location Name} — {population} — [~] {N}/{N} money pages
- [ ] `/{region}/{location-slug}/` — {Location Name} — {population} — [ ] 0/{N} money pages
```

**Sub-heading format:** `### {Region Name} ({abbrev}) — ({unique}/{total} pages)  ({complete}/{total} {location type}s)`

Where:
- `unique` = count of location rows with at least one money page unique in this
  region
- `total` = total money pages possible in this region (locations × services)
- `complete` = count of locations where ALL money pages are unique
- `total locations` = total qualifying locations in this region

#### 7c. Per-location line format

```
- [{status}] `/{region}/{location-slug}/` — {Location Name} — {population} — [{money_status}] {N}/{total} money pages
```

| Field | Description |
|---|---|
| `status` | Overall location status: `[x]` if all money pages unique, `[~]` if in progress, `[!]` if some exist, `[ ]` if none |
| `region` | Region slug |
| `location-slug` | Location slug (URL segment) |
| `Location Name` | Human-readable name |
| `population` | Population with shorthand suffix (e.g. `2K`, `197K`, `1650K`) |
| `money_status` | Status of money pages for this location (same symbols) |
| `N` | Count of money pages that have `unique: true` |
| `total` | Total money pages expected (number of services) |

**Population formatting:** use shorthand with `K` suffix — `1K`, `25K`, `197K`,
`1650K`. No commas.

**Sorting:** locations within a region are sorted alphabetically by slug. Regions
are sorted alphabetically by slug.

## Generator script contract

The generator script (e.g. `source/scripts/gen-pages-tracker.js`) reads the content folder
and produces `TRACKER.md`. Here is the input/output contract.

### Inputs (what the script reads)

| Input | Source | Purpose |
|---|---|---|
| Core page definitions | Project config or a hardcoded list |知道哪些核心页面存在 |
| Service list | `src/data/services.json` (or equivalent) | Hub count, service names, money-page total per location |
| Region list | `src/data/{regions}.json` (or equivalent) | Region names, slugs, abbrevs, location counts |
| Location list | `src/data/{locations}.json` (or equivalent) | Location names, slugs, populations, parent regions |
| Content folder | `src/content/` (or the project's content dir) | Per-file `unique: true` frontmatter check |
| Manual status overrides | The existing `TRACKER.md` (parsed) | Preserve `[~]` and `[!]` flags across regenerations |

### Outputs (what the script writes)

A single `TRACKER.md` file at the project root, matching the exact layout above.

### Derivation rules

| What | How derived |
|---|---|
| Core page status | Check if `src/content/core/{slug}.md` exists AND has `unique: true` in frontmatter |
| Hub status | Check if `src/content/hubs/{slug}.md` exists AND has `unique: true` |
| Region page status | Check if `src/content/regions/{slug}.md` exists AND has `unique: true` |
| Location status | `[x]` if its page + ALL money pages have `unique: true`; `[!]` if its page or some money pages exist but not all unique; `[ ]` if none exist |
| Money page status | Check if `src/content/money/{region}/{location}/{service}.md` exists AND has `unique: true` |
| Summary counts | Unique = count of `[x]` rows per category; Total = theoretical max from data files |
| Section checkmarks | Append ` ✓` to section header when unique = total |

### Status preservation rules

1. Parse the existing `TRACKER.md` (if it exists) before regenerating.
2. Collect all `[~]` and `[!]` entries into a `Set` keyed by their URL path.
3. After deriving fresh statuses from the filesystem, overlay the preserved `[~]` and
   `[!]` entries — they override the derived `[ ]` or `[x]`.
4. Write the output.

This ensures claimed/rework-flagged rows survive regeneration.

### Frontmatter check

The script reads each content file's frontmatter to check for `unique: true`. The
check must be:

- **Line-ending-agnostic:** match `/^unique:\strue\s*$/m` (handles both `\r\n` and
  `\n`).
- **Exact:** `unique: true` on its own line — not `unique:true`, not `unique: "true"`,
  not indented.

### Content folder structure (expected)

```
src/content/
├── core/           # Core pages (index, about, contact, faq, privacy, terms, services, locations, 404)
├── hubs/           # Service hub pages ({service-slug}.md)
├── regions/        # Region/state pages ({region-slug}.md)
├── locations/      # Location pages ({region}/{location-slug}.md)
└── money/          # Money pages ({region}/{location}/{service-slug}.md)
```

The script walks these directories to discover all content files and derive statuses.

## Scripts

| Script | Location | Purpose |
|---|---|---|
| `gen-pages-tracker.js` | `source/scripts/` | Scans `src/content/`, derives statuses from `unique: true`, preserves `[~]`/`[!]` flags, writes `TRACKER.md` |
| `claim-state.mjs` | `source/temp/` | Claims/unclaims a region (state) in the tracker — flips region + location rows to `[~]` so parallel PCs don't duplicate work |

### Claiming a region before writing

Before writing a region's content, claim it first:

```bash
node source/temp/claim-state.mjs <region-slug>        # claim (sets [~])
node source/temp/claim-state.mjs <region-slug> --unclaim  # unclaim (resets to [ ])
```

The script flips the region row and all its location/money rows to `[~]`. After
claiming, `git add` + `git commit` + `git push` so peers see the claim. Never
pre-claim the whole backlog — only the region currently being worked.

### Regenerating the tracker

```bash
npm run gen:tracker
# or: node source/scripts/gen-pages-tracker.js
```

Run after every content batch. Never hand-edit `TRACKER.md`.

## Checklist (done when)

- [ ] `TRACKER.md` exists at the project root.
- [ ] Summary table totals match the data files (regions × locations × services + hubs + core).
- [ ] Every content file in `src/content/` has a corresponding row in the tracker.
- [ ] `[x]` rows have `unique: true` in their content file.
- [ ] `[~]` and `[!]` flags are preserved across regeneration.
- [ ] No `[ ]` row has a content file with `unique: true`.
- [ ] Section headers show ` ✓` only when all entries are `[x]`.
- [ ] Population formatting uses shorthand (`2K`, `197K`) with no commas.
- [ ] Money page sub-headings show correct complete/total counts per region.

## Notes & gotchas

- The tracker is a **derived artifact** — the content folder is the source of truth,
  not the tracker. If they disagree, regenerate the tracker.
- Never hand-edit totals, status symbols, or row entries — always re-run the generator.
- The `unique: true` frontmatter line must sit on its own line (build gate regex is
  line-ending-agnostic).
- Population data is internal-only — used in the tracker for reference, never published
  on pages.
- Empty regions (0 qualifying locations) still appear in the tracker with a region page
  row but no location/money rows.
